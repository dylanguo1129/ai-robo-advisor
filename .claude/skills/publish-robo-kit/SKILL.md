# Publish your own copy of the Robo-Kit web page

This publishes the page in `web/` as a **new private artifact owned by the person running this session**. Because they
own it, the in-page assistant works for them and runs on their own Claude plan. Nobody else's artifact or plan is
involved, and nothing is shared with anyone.

Anthropic only lets the assistant run in a shared artifact for the owner and members of the owner's Team or Enterprise
organization. Everyone else gets their assistant by publishing their own copy, which is what this does.

## Requirements (check first)

- Claude Code (the `claude` CLI, or the Code tab of the Claude desktop app, version 1.13576.0 or later), signed in
  with `/login` to a **Pro, Max, Team or Enterprise** claude.ai account. Sessions on an API key (including an
  `ANTHROPIC_API_KEY` environment variable), a gateway token, Amazon Bedrock, Google Vertex or Microsoft Foundry cannot
  publish artifacts.
- The session runs in this repository's root folder (it contains `web/publish.json`).
- Python 3 (the check below uses the standard library only).

If the Artifact tool is not available in this session, or publishing is refused because of the account or sign-in,
stop and explain the first requirement. Do not offer another way to host the page: the data snapshot is licensed for
personal use only.

## Steps

1. **Say which version is being published.** Run `git log -1 --format="%h %cs %s"` and `git status --short -- web`.
   Tell the person the commit. If `web/` has local changes, say the copy will include them and ask whether that is
   intended. If they want the latest version, they can run `git pull` themselves first.

2. **Run the check.** Run `python scripts/check_publish.py` (or `python3 ...`). It lists the files that make up the page
   (`web/publish.json`), checks that list against what the page loads and against the Artifact size limits, summarises
   the three data files, and ends with the publish settings. If it prints PROBLEMS, stop and show them; do not publish
   a partial page.

3. **Look at what you publish.** Read `web/index.html` and the `.js` files in the list in full (the page code, about
   250 KB; read `robokit.js` and `guide.js` in chunks). The two files in `web/data/` that are published are
   single-line JSON tables generated by `python -m robokit bundle` (1.4 MB: fund names and figures, and monthly return
   series stored as base64; the page offers Canadian-listed ETFs only, so `us.json` is not published). The check
   has already parsed each of them completely and scanned every text value for markup, script links and hidden
   control or text-direction characters; its summary says what each file holds. Then read the text a person will
   see: pretty-print `web/data/core.json` (`python -m json.tool web/data/core.json`) into a file in your temp or
   scratch folder, never inside the repository, and read its questions, glossary, scenario notes and headlines. The
   rest of the data is tickers, fund names, numbers and base64 return series that the check has scanned; that is the
   review this page needs, though you may scan or sample `ca.json` further with your own script. Never
   edit these files. The page is published as it is: no design step is needed.

4. **New copy or update?** List the person's own artifacts (`Artifact`, `action: "list"`). If one is titled
   "Robo-Kit" (a copy they published before, or the original if they are the project owner), ask whether to update it
   (same link, the same people keep access) or make a new one. The argument `update` means update; if several match,
   show each one's link and last-updated time and ask which. If there is none, make a new one.

5. **Publish** with the Artifact tool, using the settings the check printed. If the tool's instructions ask you to
   load a skill or guide before passing `capabilities`, do that first.
   - New copy: `file_path` = `web/index.html`, `files` = the printed map (published path to `web/...` source),
     `capabilities` = the printed capabilities (`sample` for the optional Claude answers, `comments` with
     `composer_only` for "Comment on this screen", `downloads` for the summary), and the printed `title`, `icon` and
     `description`. No `url`.
   - Update: first read the existing artifact (`action: "read"` with its `url`) and list its files (`action: "list"`,
     `scope: "files"`, the same `url`); the tool refuses to replace files it has not seen. Then publish with that
     `url` and the same `file_path`, `files` and `title`. Leave out `icon` and `description` (they carry over), and
     pass the printed `capabilities` when the read shows the copy lacks any of them (a declaration replaces whatever
     is stored), and leave them out otherwise.
   Do not change any file in `web/`, and publish only the files in the list (never `dev_mock.js`, `mock.html` or the
   `test_*` files).

6. **Tell the person:**
   - their link, the commit it was published from, and that the page is private to them;
   - the first time they send the assistant a message, Claude asks once for permission to use their plan; they can
     pick Quick, Standard or Deep under "Assistant";
   - the data date the check printed ("prices through ..."); the copy never updates by itself, so to get a newer
     version they pull the repository and run `/publish-robo-kit update`;
   - keep it private. Artifacts that use Claude cannot be shared with "Anyone with the link", and the snapshot is
     licensed for personal use. If they invite someone by email, that person sees the page without the assistant
     (unless they are in the same Team or Enterprise organization); they can publish their own copy the same way.
